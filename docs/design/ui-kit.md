# Дизайн-система и UI-набор

Longevypedia выглядит как научное издание, а не как SaaS-лендинг: плотный текст,
спокойные цвета, один акцент, никакой декоративной анимации. Дизайн-система — это
токены в SCSS, базовые стили и компоненты в `app/components/ui/`; живой каталог —
`/ui-kit`, индекс — `app/pages/ui-kit/page.php`, список страниц — `data/ui-kit.php`.

## Принципы

1. **Научный.** Данные важнее оформления: таблицы, числа, единицы, источники. Цвет
   сигнализирует статус, но никогда не заменяет слово.
2. **Редакционный.** Основной текст — серифный, с мерой строки 68ch и спокойным
   межстрочным. Заголовки и интерфейс — гротеск.
3. **Минималистичный.** Одна заливка акцента на экран, тени почти незаметны, радиусы
   умеренные. Никаких градиентов, неона, стекла и «карточек в карточках».
4. **Честный.** Направление результата и качество доказательств — разные оси; компонент
   `evidence` не выводит одно из другого.
5. **Доступный.** Контраст проверяется расчётом, фокус виден, движение отключается
   системной настройкой.

даёт 3.38:1, то есть ниже AA. Поэтому `--color-accent` остаётся для рамок, иконок и
линеек, а кнопки красятся в `--color-accent-fill` (белый текст — 4.84:1) и
`--color-accent-fill-hover` (4.84:1 на hover-значении проверяется отдельной парой в
`/ui-kit/accessibility`).

Тёмная тема — **не инверсия**. Значения подобраны отдельно: фон почти чёрный с зелёным
подтоном, поверхности светлее фона, бренд светлее, чтобы держать контраст. Там, где цвет
палитры не годится как текст, заведён отдельный `-text`-токен (например,
`--color-success-text` на `--color-success-soft`).

## Типографика

| Токен | Значение | Применение |
| --- | --- | --- |
| `--text-xs` | `0.75rem` (12px) | служебные подписи, бейджи |
| `--text-sm` | `0.875rem` (14px) | вторичный текст, таблицы |
| `--text-base` | `1rem` (16px) | интерфейс |
| `--text-lg` | `1.125rem` (18px) | лид, крупные поля |
| `--text-xl` | `1.25rem` (20px) | h3, заголовки карточек |
| `--text-2xl` | `1.5rem` (24px) | h2 |
| `--text-3xl` | `clamp(1.625rem, 1.45rem + 0.7vw, 1.875rem)` | h1 каталога |
| `--text-4xl` | `clamp(1.875rem, 1.55rem + 1.3vw, 2.25rem)` | h1 страницы |
| `--text-5xl` | `clamp(2.125rem, 1.6rem + 2.4vw, 3rem)` | hero главной |

Веса: 400, 500, 600, 700. Межстрочные: `--leading-tight` 1.15 (заголовки),
`--leading-snug` 1.3, `--leading-normal` 1.5, `--leading-table` 1.4,
`--leading-relaxed` 1.7 (проза). Трекинг: `--tracking-tight` −0.011em для крупных
заголовков, `--tracking-wide` 0.06em для надзаголовков (`.eyebrow`).

Правила:

- Интерфейс — Inter (`--font-ui`); проза и заголовки — Source Serif 4 (`--font-serif`);
  код — `--font-mono`.
- Мера строки — `--layout-measure: 68ch`; `.prose` не растягивается шире.
- Числа в таблицах — `font-variant-numeric: tabular-nums`.
- Заголовок `h1` один на страницу; иерархия не перескакивает уровни.

## Отступы, радиусы, тени

Шкала отступов — шаг 4px: `--space-1` 0.25rem, `--space-2` 0.5rem, `--space-3` 0.75rem,
`--space-4` 1rem, `--space-5` 1.25rem, `--space-6` 1.5rem, `--space-8` 2rem,
`--space-10` 2.5rem, `--space-12` 3rem, `--space-16` 4rem. Используйте токены, а не
`margin: 13px`.

| Токен | Значение | Где |
| --- | --- | --- |
| `--radius-sm` | 0.25rem | бейджи, чипы, мелкие кнопки |
| `--radius-md` | 0.5rem | карточки, поля, кнопки |
| `--radius-lg` | 1rem | крупные панели, врезки |
| `--radius-full` | 999px | круглые индикаторы, «таблетки» |
| `--shadow-sm` | `0 1px 2px rgb(30 41 51 / .07)` | карточки в покое |
| `--shadow-md` | `0 6px 20px rgb(30 41 51 / .09)` | hover, поповеры |
| `--focus-ring` | `0 0 0 2px var(--color-bg), 0 0 0 4px var(--color-brand)` | фокус снаружи |
| `--focus-ring-inset` | внутреннее кольцо | фокус на тёмной заливке |

В тёмной теме тени чернее и плотнее (`rgb(0 0 0 / .5)`), потому что светлая тень на
тёмном фоне не читается.

### Точки перехода

Медиазапрос не принимает значение из CSS-переменной — `@media (max-width: var(--bp-md))`
невалиден, — поэтому точки живут SCSS-переменными в одном файле
`app/client/styles/_breakpoints.scss`:

| Переменная | Значение | Когда срабатывает |
| --- | --- | --- |
| `$bp-xs` | 30rem (480px) | узкий телефон: одна колонка, крупные отступы |
| `$bp-sm` | 40rem (640px) | телефон: шапка переносится, боковые колонки вниз |
| `$bp-md` | 48rem (768px) | сетки схлопываются в одну колонку |
| `$bp-lg` | 56rem (896px) | планшет: узкая боковая колонка ещё рядом с текстом |
| `$bp-xl` | 60rem (960px) | ноутбук: статья и содержание не помещаются рядом |
| `$bp-2xl` | 64rem (1024px) | широкий ноутбук: компактные варианты полей и навигации |

Файл подставляется в каждую единицу компиляции через
`css.preprocessorOptions.scss.additionalData` в `vite.config.js` (плюс `loadPaths` на
`app/client/styles`). Это нужно потому, что стили компонентов вырезаются из шаблонов в
`.bolt/client/generated/…` и компилируются отдельными файлами: относительный `@use` из них
не нашёл бы общий файл. Значения при этом остаются в одном месте, а не копируются в каждый
компонент — за этим следит тест `testBreakpointsComeFromTheSharedScale`: он падает, если в
`app/` появится медиазапрос с числом мимо шкалы.

Media queries — desktop-first (`max-width`), потому что базовый макет широкий.

Каркас: `.page` — flex-колонка на `100dvh`, `.page__main` растягивается, `.container`
ограничивает ширину и добавляет `--layout-gutter`. Шапка липкая, `scroll-padding-top`
учитывает её высоту, чтобы якоря не прятались под шапкой.

**Наведение на заливку обязано переопределить цвет текста.** Общее правило базового
слоя `a:hover { color: var(--color-brand-hover) }` имеет специфичность (0,1,1) и перебивает
одиночный класс вроде `.home-cta` (0,1,0). Если правило наведения меняет только
`background`, текст остаётся бирюзовым: `#105651` на коричневой заливке `#8f5024` — это
1.35:1, то есть не читается. Поэтому каждое правило `:hover`, меняющее заливку на
акцентную или брендовую, задаёт и `color`; за этим следит
`testHoverOnFilledSurfaceRestatesTheTextColour`.

**Прижатый к низу подвал — не всегда благо.** `min-height: 100dvh` на `.page` вместе с
`flex: 1` на `.page__main` отдаёт остаток высоты окна `main`, и на высоком окне под
последним блоком вырастает полоса пустого фона в сотни пикселей — она читается как сбитый
отступ, а не как «страница кончилась». Главная поэтому отменяет приём:
`.page--home .page { min-height: 0 }` и `.page--home .page__main { flex: none }`. Тянуть
подвал на остаток нельзя: он превращается в пустую плиту своего цвета
(`footer height=389` при окне 2400px). За этим следит
`testHomePageDoesNotStretchToViewportHeight`.

**`.page__main` не даёт боковых отступов** — их даёт только `.container`. Поэтому любая
страница, которая начинает разметку с собственного `<div>`, обязана либо обернуть его в
`.container`, либо повторить `max-width`/`margin-inline`/`padding-inline` сама; иначе
заголовок и карточки прилипают к краю окна. Это проверяется тестом
`testUiKitIndexIsInsideThePageContainer`.

**Сетки пишутся как `minmax(0, 1fr)`.** Голый `1fr` означает `minmax(auto, 1fr)`, то есть
минимальная ширина колонки равна `min-content` содержимого: длинная цитата или строка
таблицы распирает всю страницу и появляется горизонтальная прокрутка. Тот же запрет —
для `white-space: nowrap` на длинных текстах: он допустим только для коротких
идентификаторов (DOI, PMID).

**Шапка на узком экране переносится.** На `max-width: 48rem` навигация скрывается, а
форма поиска уходит во вторую строку (`flex: 1 0 100%`), поэтому бренд, переключатель темы
и ссылка на GitHub остаются в первой. Без этого поиск с `max-width: none` выталкивал
кнопки за край.

## Тёмная тема

Токены тёмной темы описаны миксином:

```scss
@mixin dark-tokens { /* ... */ }

:root { color-scheme: light; /* светлые значения */ }

@media (prefers-color-scheme: dark) {
	:root:not([data-theme='light']) {
		@include dark-tokens;
	}
}

:root[data-theme='dark'] {
	@include dark-tokens;
}
```

Логика:

- **auto** (по умолчанию) — атрибута `data-theme` нет, работает системная настройка;
- **light** — `data-theme="light"` отключает тёмные правила даже при тёмной системе;
- **dark** — `data-theme="dark"` включает тёмные токены принудительно.

Переключатель — `app/client/theme.ts`: ключ `localStorage['longevypedia.theme']`,
пункт списка `[data-theme-choice]` применяет своё состояние, `aria-pressed` отмечает
выбранное, `aria-label` триггера обновляется («Colour theme: dark»), состояние
дублируется в `dataset.themeState` для стилей иконок.

Вспышки нет: в `<head>` layout стоит инлайновый скрипт, который читает
`localStorage` и ставит `document.documentElement.dataset.theme` **до** первой отрисовки.
Без него страница успевала бы показаться светлой и переключиться.

Компоненты не должны знать про тему: они используют токены. Единственное исключение —
иконки солнца/луны в шапке, где видимость зависит от `prefers-color-scheme` и
`[data-theme='dark']`.

## Консистентность

Правило простое: если элемент есть в наборе, страница его вставляет, а не повторяет
разметку. Расхождение начинается с одной кнопки — рядом с кнопкой набора появляется
вторая высота, второй фокус и второе состояние наведения.

Что проверяется тестами:

- `testHeaderControlsAreKitButtons` — переключатель темы и ссылка на исходники в шапке
  это `ui/theme-toggle` и `ui/button`, а не собственные `.theme-toggle`;
- `testTemplatesDoNotHandRollButtons` — вне `app/components/ui/` нет `<button>`,
  `<select>`, `<textarea>` и `<table>`: контролы и таблицы берутся из набора;
- `testEveryCustomPropertyIsDefinedOrAssignedLocally` — шаблон не ссылается на
  несуществующий токен;
- `testAccentIsNotUsedAsTextColour` и `testHoverOnFilledSurfaceRestatesTheTextColour` —
  цвет текста на заливке задаётся явно.

Что осталось собственной разметкой осознанно: списки ссылок (подвал, результаты
поиска, связи документа, тематики на главной) и ссылки вида «все документы». В наборе
нет компонента «список ссылок»: оборачивать `<ul>` в карточки значило бы утяжелить
страницу, где ссылки и так стоят столбиком. Общее у них — только типографика, она
приходит из базового слоя.

## Плитки и таблицы

**`ui/card` внутри `display: grid`.** Плитка — элемент сетки, а не блок с
`width: 100%`: ширина приходит от колонки, поэтому в образце и в индексе набора
карточка растягивается на свою клетку, а не на страницу.

**Длинная таблица прокручивается внутри себя.** `ui/data-table` с `sticky => true`
получает `max-height: min(80vh, 44rem)` и `overflow: auto`, а шапка —
`position: sticky; top: 0`. Без своего скролл-контейнера `top: 0` прилипает к окну, и
шапка уходит под шапку сайта. `border-collapse` у такой таблицы — `separate`:
Chrome теряет нижнюю границу прилипшей ячейки при `collapse`. Заголовок таблицы
контраста на `/ui-kit/accessibility` — первый потребитель этого режима.

## Состояние, а не только подпись

Кнопка копирования исходника меняет три вещи: подпись (`Копировать` → `Скопировано`
→ `Не удалось`), цвет (успех `--color-success-text`, ошибка `--color-danger-text`) и
скрытый `role="status"`, связанный через `data-copy-status`. Замена подписи сама по
себе не озвучивается: фокус остаётся на кнопке, а скринридер не перечитывает
изменившийся текст. Логика — `app/client/copy-code.ts`, `initCopyButtons()`.

Кнопка-иконка не заменяет действие со словом: `Копировать` — это действие, а не
состояние, поэтому подпись остаётся видимой. Значок `cog` в образцах не используется:
в 16 px он читается как клякса, а не как шестерёнка.

## Знак в контроле выбора

`ui/choice` рисует галочку и точку **отдельными элементами** внутри контрола с
`display: grid; place-items: center`, а не псевдоэлементами с `clip-path` и `inset`.
Иначе знак смещается: `clip-path` считается от бокса целиком, и треугольник галочки
уезжает вниз, а точка с `inset` отступает от границы вместе с её толщиной. У тумблера
кружок центруется по высоте через `translateY(-50%)`, а не фиксированным `top`.
Образец «Отмеченные» существует именно для того, чтобы центровку было видно: все
остальные образцы выключены, и знак в них не рисуется.

## Заглушка загрузки

`ui/skeleton` всегда получает ширину (`width: 100%`, у варианта `card` —
`max-width: 22rem`). Строки внутри заданы процентами, а у flex-элемента без ширины
проценты считаются от нуля: заглушка схлопывалась в пустое место и в образце
выглядела как «ничего не нарисовано».

## Переключатель темы — список, а не цикл

Тема имеет три состояния, как в системных настройках: `auto` (по системе), `light`,
`dark`. Кнопка-значок их не различает: по луне нельзя понять, выбрана тёмная тема или
она просто следует за системой, а вернуться к «как в системе» можно было только
нажав дважды. Поэтому `ui/theme-toggle` — это `<details>` с тремя пунктами, где
текущий отмечен галочкой, а подпись кнопки-триггера содержит выбранное состояние
(`Colour theme: system`). Значок показывает выбранное, а не следующее: половина
круга — «как в системе», солнце — светлая, луна — тёмная.

`<details>` вместо кнопки: раскрытие работает без JavaScript, а `app/client/theme.ts`
только применяет выбор, ставит `aria-pressed` и закрывает список. Триггер —
`<summary>` с классами `ui-button`, а не `components::ui/button`: кнопка набора
рендерит `<button>`, а открыть `<details>` умеет только `<summary>`. Классы те же,
поэтому размер, фокус и наведение совпадают с соседними кнопками.

Два соседних значка в шапке собраны в одну группу `.site-header__tools` с зазором
`var(--space-1)`: у кнопок набора свои 8 px внутренних полей, и общий зазор шапки в
20 px давал 36 px между самими значками — они читались как два несвязанных элемента.

## Вложенный блок не рисует свою рамку

Карточка исследования (`ui/research-metadata`) содержит список «поле — значение» и
таблицу исходов. Каждый из них умеет рисовать свою рамку — и внутри карточки это
давало три вложенных прямоугольника. Поэтому у обоих есть вариант без границ:
`ui/key-value` принимает `dividers => false` (класс `ui-kv--plain`), `ui/data-table`
— `variant => 'plain'` (класс `ui-table--plain`). Внутри карточки блоки разделяет
воздух, а не линии; рамка остаётся одна — карточки.

`ui/data-table` собирает обёртку через `attrs($wrapperAttrs)`, а не строкой класса:
пока класс был записан в шаблоне, переданные `attrs` (например, отступ
`ui-research-meta__outcomes`) молча терялись.

## Направление ≠ качество доказательств

Компонент `ui/evidence.php` принимает два независимых параметра:

- `direction`: `supports`, `contradicts`, `mixed`, `neutral`, `insufficient`;
- `quality`: `high`, `moderate`, `low`, `very-low`, `unassessed`.

Их нельзя выводить друг из друга. Исследование может быть методологически слабым
(`low`), но показывать рост (`supports`); может быть сильным (`high`) и не находить
эффекта (`neutral`). Компонент рисует обе шкалы и не «усредняет» их в один цвет.
Правила присвоения — [`../specifications/methodology.md`](../specifications/methodology.md).

Тот же принцип в `ui/claim-status.php`: `confidence` и `evidence_direction` — отдельные
бейджи, а не один «светофор».

Направление кодируется цветом только вместе с подписью: `supports` — зелёный,
`contradicts` — красный, `mixed` — янтарный, `neutral` — серый, `insufficient` — синий.
Синий у «недостаточно данных» не случаен: серый в палитре уже занят нейтральным
результатом, и две разные вещи не должны выглядеть одинаково. Качество доказательств
цветом не кодируется вовсе — это шкала из четырёх делений и текстовая категория.

**Акцентный цвет не бывает цветом текста.** `--color-accent` (#c47a45) даёт 3.17:1 на
фоне и 3.38:1 на поверхности — ниже AA для обычного текста, поэтому он остаётся для
заливок, рамок и линий, а текст берёт `--color-accent-text` (#9a5a2e, 5.08:1). За этим
следит тест `testAccentIsNotUsedAsTextColour`.

## Как добавить компонент

1. **Файл.** `app/components/ui/<name>.php`: docblock с `@param`, дефолты через `??=`,
   разметка, один `<style lang="scss">` в конце.
2. **Стили.** Только токены; BEM-классы `ui-<name>__element--modifier`; тёмная тема
   бесплатно, если не хардкодить цвета.
3. **Каталог.** Добавьте страницу в `scripts/ui-kit-pages.php`: группу, `title`, `note`
   и образцы (`heading`, `explanation`, код вставки). Генератор создаст
   `app/pages/ui-kit/<name>/page.php` и обновит `data/ui-kit.php`.
4. **Сборка.** `php scripts/ui-kit-pages.php`, затем `bun run build` (или дождитесь HMR).
   Откройте `/ui-kit/<name>`: живой пример и исходник должны совпадать.

Если страницу не добавить, `data/ui-kit.php` не узнает о компоненте, и он не появится в
навигации — это самая частая забытая часть.

## Доступность

Что проверено:

- **Контраст.** `src/Design/Contrast.php` считает отношение по WCAG: 4.5:1 для обычного
  текста, 3:1 для крупного. Страница `/ui-kit/accessibility` прогоняет 34 пары (17 ролей ×
  2 темы) по текущим токенам. Все проходят AA. Минимальные значения: 3.58 (граница поля
  ввода, крупный элемент), 4.84 (текст на акцентной заливке), 4.99 (светлая,
  предупреждение на подложке), 5.34 (тёмная, подписи).
- **Фокус.** `:focus-visible` получает `box-shadow: var(--focus-ring)`; `outline: none`
  без замены запрещён.
- **Клавиатура.** Аккордеон и меню — на `<details>`; ссылки и кнопки — настоящие
  `<a>`/`<button>`; skip-link ведёт на `#main`.
- **Семантика.** Один `h1`, `aria-current` у активной навигации, `aria-live` у счётчика
  каталога и подсказок поиска, `aria-hidden` у декоративных иконок и заглушек.
- **Движение.** Глобальный `prefers-reduced-motion` отключает плавную прокрутку и
  переходы.
- **Тема.** `color-scheme` выставлен для обеих тем, переключатель имеет текстовую
  метку.

Чего нет: автоматических axe/Pa11y-прогонов, проверки порядка табуляции и скриншот-тестов.
Это ручная проверка при ревью.

## Что запрещено

| Нельзя | Почему |
| --- | --- |
| градиенты, особенно фиолетовые | визуальный шум, «AI-лендинг» |
| неон, свечение, glow | мешает чтению данных |
| glassmorphism, полупрозрачные карточки | падает контраст, ломает тёмную тему |
| SaaS-дашборд: крупные KPI, иконки в кружках, «+128%» | не соответствует жанру энциклопедии |
| эмодзи вместо иконок | разный рендеринг, непредсказуемая ширина |
| цвет без текста | статус должен читаться словом |
| анимации дольше 200 мс и «на внимание» | отвлекает от текста |
| тени-«парящие» и большие радиусы (≥ 24px) | превращает интерфейс в игрушку |
| кастомные скроллбары, курсоры | ломает системные ожидания |
| вывод качества из p-value или размера эффекта | противоречит методологии |

## Чем отличается от `bolt://ui-kit`

BOLT даёт базовый набор (`button`, `card`, `field`, `form`, `form-message`, `icon`,
`logo`, `wordmark`, `modal`, `pagination`, `seo`). Он намеренно минимален, и у его
компонентов **закрытый список вариантов**: у кнопки — `primary|outline|blue|link`, два
размера, нет `danger`/`ghost`/`loading`; у карточки — заголовок, тело, блок действий и
два варианта (`blue`, `outlined`), но нет метаданных документа, тегов и статусов.

Проект использует из него только `icon` и `seo`. Остальное — свои компоненты в
`app/components/ui/`, потому что нужны состояния и семантика, которых в BOLT нет:
направление доказательств, статус утверждения, источники с DOI/PMID, пустые состояния,
таблицы данных.

Переопределять `bolt://ui-kit/button` своим файлом по тому же пути можно, но проект так
не делает: префикс `ui/` показывает, где библиотека, а где наш код, и обновление BOLT не
задевает наши компоненты.

## Почему стили лежат в PHP-файлах

`<style lang="scss">` внутри `app/components/ui/*.php` — осознанное решение, а не
случайность:

- BOLT (`bolt/src/View/AssetExtractingEngine.php` и плагин `componentAssets`) вырезает
  такие блоки из шаблонов и собирает в `.bolt/client/generated/main/index.ts`. Стили
  компонента попадают в общий бандл автоматически, без ручной регистрации.
- Схема «шаблон + отдельный `client/styles/components/<name>.css`» потребовала бы
  синхронизировать два файла: переименовали класс — забыли CSS. Здесь разметка и стили
  рядом, и ревью видит их вместе.
- Стили страницы (`app/pages/**`) работают так же; в `main.scss` лежит только общее.

Ограничение: `<style inline>` (без `lang`) в бандл не попадает — он остаётся в HTML.
Для стилей проекта используйте `lang="scss"`; инлайн допустим только для критического
CSS, которого в проекте нет.
